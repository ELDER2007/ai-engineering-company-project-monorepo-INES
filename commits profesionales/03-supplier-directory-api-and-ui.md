Add supplier directory: FastAPI + TinyDB API and application UI

Replace the spreadsheet that Purchasing/HR used to keep suppliers with a
single source of truth: a REST API backed by TinyDB and a web page to
browse and manage it. Nothing enters the database unless it passes the
Pydantic models, and the API starts with the 15 suppliers from the
CONTEXT already loaded.

API (services/api)
- models.py: Pydantic models built from CONTEXT-suppliers.md. Fields:
  name, country (Spain | USA), categories (9 valid values, at least
  one), monthly_rate (> 0), currency, status (active | suspended),
  updated_at and the optional contract_renewal_date, contact_email and
  notes. Currency must match the country (Spain -> EUR, USA -> USD).
  Input models forbid extra fields, so a client cannot send updated_at
  or id. Invalid input is rejected with 422 before it reaches TinyDB.
- database.py: TinyDB initialisation and data access. updated_at is
  generated by the server and stamped when the monthly rate changes.
- routes/suppliers.py: POST /suppliers (201 with the new id),
  GET /suppliers with optional ?country= and ?category= filters,
  GET /suppliers/{id}, PATCH /suppliers/{id}, PATCH .../rate,
  PATCH .../status and DELETE /suppliers/{id}, plus the dedicated
  /search/by-country and /search/by-category endpoints. 404 for unknown
  ids, 422 for invalid input. Routes are served at /suppliers and also
  at /api/suppliers because the Vite proxy only forwards /api.
- Suspended suppliers are never deleted (CONTEXT): DELETE returns 409
  for them and 204 for active ones.
- seed.py: loads the 15 CONTEXT suppliers, validated through the same
  models. Idempotent (skips names already present, never duplicates),
  supports --reset and prints how many records were inserted. Runs with
  `uv run seed` (script declared in pyproject.toml). At startup the API
  seeds only a completely empty database, so a renamed supplier is not
  re-inserted.
- contact_email must look like an email when provided.

UI (uis/application/app/suppliers)
- New React + Vite + Tailwind app; the page was moved from
  uis/backoffice with git mv to match the delivery structure.
- Lists every supplier from the API with name, country, categories,
  monthly rate and currency, renewal date and status.
- Country and category filters update the list without reloading.
- Creation form with client-side validation; when the API rejects the
  input, its message is shown.
- Inline rate editing and an activate/suspend toggle; each row updates
  after the API responds.
- Active and suspended suppliers are visually distinct; contracts
  renewing within 60 days are highlighted.

Problems found and resolved along the way
- Routes did not match the requested /suppliers path: served under both
  prefixes instead of breaking the frontend proxy.
- The API silently ignored a client-sent updated_at: now a 422.
- The seeder skipped everything when the database was not empty: now it
  inserts only what is missing.
- `uv run seed` failed from the repository root: documented the working
  directory and the --project form.
- DELETE contradicted the CONTEXT rule about suspended suppliers: now a
  409.
- contact_email was only validated in the browser: now validated by the
  API too.
- The renewal highlight was barely visible: stronger background and a
  side bar, tested with dates at 30 and 61 days.
- A colour check passed while a CSS transition was still running and
  compared two greens: it now waits and asserts the exact colours.
- A background task from an earlier session switched branches in the
  middle of the restructuring: recovered with git stash, no work lost.

Verification
- 42 pytest tests: model fields, status and rate rejection before
  TinyDB, server-generated updated_at, every endpoint and its status
  codes, DELETE rules, email validation.
- 28 Playwright checks against the real API and UI, passing on
  Chromium and Firefox: list, filters without reload, form validation
  and API error display, rate edit, status toggle, active/suspended
  styling and renewal highlight.
- Data persists across a server restart; a fresh clone of the branch
  seeds, tests, builds and type-checks cleanly.

Known limits
- TinyDB is not safe with several processes writing at once; the plan
  is to migrate to Postgres once the ORM is ready.
- The UI was tested on Chromium and Firefox only.
